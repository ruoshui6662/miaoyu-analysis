# G0 工程基线收口：交付规划（v1.0）

> 制定：2026-09-02 ｜ 状态：代码完成，待人工验收 ｜ 范围：现有单次分析闭环，不扩展为持续监测或多租户服务。

## 1. 第一性原理与边界

本阶段的目标不是增加功能，而是让用户界面中的承诺与代码的实际行为一致。单次分析可靠性的最小因果链是：

```text
保存设置 → 下一次任务读取同一份设置 → 采集 / AI 执行 → 进度如实反映状态
→ 报告与核查结果彼此隔离 → 可在无网络、无密钥环境重复验证
```

因此，G0 只修复这条链路的断点；不引入 `Mention` 表、定时调度、身份认证或新的爬取能力。这些分别属于 G1、G2、G3。

## 2. 调研结论

| 编号 | 已确认的现状 | 根因 | 风险 |
|---|---|---|---|
| G0a | `pipeline.run_analysis()` 会调用 `config.reload()`，但 `searx_client.py` 和 `collector.py` 以 `from config import X` 保存导入时快照 | Python 名称绑定不会随模块变量重新赋值而更新 | 设置页保存的 SearXNG 地址、超时、采集组不一定进入下一任务 |
| G0b | 四个 AI 阶段向 `chat_json()` 传入 `on_chunk`；该函数走非流式 `chat()`，不会产生分段内容 | 进度文案宣称“已生成 N 字”，数据路径并不支持 | 用户看到与实际不符的进度，排障困难 |
| G0c | URL 核查将当日完整结果存入单一 `_cache["urls"]` | 缓存键不是 URL 本身 | 同日第二份报告可能拿到第一份报告的链接状态 |
| G0d | 报告名直接使用主题；docx 临时 JSON 使用秒级时间戳 | Windows 非法字符与并发命名冲突未处理 | 特殊主题导出失败；并发任务可能误删或覆盖临时文件 |
| G0e | 当前没有离线自动化测试 | 正常路径依赖网络、SearXNG、AI 服务商 | 回归只能靠人工长链路验证 |

## 3. 交付拆分与验收

| 子项 | 实施 | 验收方式 |
|---|---|---|
| G0a 配置一致性 | 所有任务期配置均从 `config` 模块动态读取；`SearxClient` 在实例化时读取当前 URL/超时；采集组和抓页超时同样动态读取 | 单测替换运行时配置后，新的客户端、采集组选项与请求超时立即改变；不需要重启 |
| G0b 真实进度 | 保留稳定的“阶段开始 / 调用中 / 成功或失败”进度；删除不可达的“已生成 N 字”承诺 | 单测断言四个阶段不会向非流式路径传递流式回调；页面轮询仍可看到明确阶段 |
| G0c 缓存隔离 | 缓存粒度改为每个规范 URL、自然日失效；重复 URL 只核查一次 | 两批 URL 在同一日分别得到各自结果；交集只复用交集 URL |
| G0d 安全命名与临时文件 | 主题清洗为可读、安全的文件段；使用随机临时 JSON 并始终清理；图表临时文件加随机后缀 | 包含 `/:*?` 的主题能生成 JSON/MD/DOCX 路径；并发临时文件名不重复 |
| G0e 离线回归 | 标准库 `unittest` 覆盖以上逻辑，并提供 Flask 健康检查冒烟 | `python -m unittest discover -s tests -v` 无网络、无 AI Key 通过 |

## 4. 实施顺序

1. 先补运行时配置读取和单元测试，保证设置语义正确。
2. 收敛 AI 进度文案到实际可观察的阶段状态，并以测试防止回归。
3. 修复 URL 缓存、文件名与临时文件的隔离。
4. 执行离线测试、编译检查和 Flask 冒烟；最后启动本地网页让用户手工验证。

## 5. 不变量

- 任务开始后读取一个一致的当前配置；已启动任务不在中途被设置页修改影响。
- 缓存可以节省重复请求，但不能向另一个 URL 返回结果。
- 进度只能陈述已发生或正在发生的事实，不能伪造流式字数。
- 用户主题是数据，不可直接作为操作系统文件名。
- 自动化测试不访问真实 SearXNG、网页或 AI 接口，也不修改正式 `data/` 内容。

## 6. 用户手工验收（实施完成后）

1. 在设置页改 SearXNG 地址和采集组，保存后不重启服务，发起一次分析，确认任务使用新设置。
2. 发起 AI 分析，确认进度显示当前阶段而非虚假的“已生成 N 字”。
3. 用 `G0 / : * ? 文件名` 之类的主题生成报告，确认网页历史、Word 和 PDF 导出正常。
4. 保持浏览器开启，由用户决定是否继续 G1；本阶段不执行 Git 提交或推送。
