# 信源精细化 · 规划（网站级 + 热榜榜单级）

> 版本 v0.1 ｜ 2026-09-01 ｜ 状态：规划
> 目标：把信源从"4 个粗组"（news/wechat/web/video）细化为"网站级 + 热榜榜单级"，
> 页面可勾选、可手动添加；为后续"热榜监测/定时任务"打好信源地基。

---

## 0. 第一性结论（先行）

1. **网站级信源：完全可行，零新增外部依赖。**
   采集环已具备域名解析（`domain_of`）、可信度分级、媒体名识别（`source_name`）、结果级过滤。
   勾选网站 → 采集结果按域名白名单保留/加权即可；再配合 SearXNG 的 `site:` 语法做精确查询。
2. **热榜榜单级信源：可行，需新增"热榜采集器"模块。**
   SearXNG 提供不了实时榜单数据，需独立抓取公开榜单接口（微博热搜/知乎热榜/B站热门/百度热搜）。
   ✅ 与规划中的 C2（热榜监测）合并落地，一次开发两个能力。
3. **数据模型上"信源"统一为四要素**：`名称 | 域名(集合) | 类别 | 采集方式`，
   勾选/手动添加都落同一张表，未来加新信源 = 加一行数据，不需要改代码结构。

## 1. 信源分类方法（目录式，三层）

```
L0 信源等级（S/A/B/C/D，决定"能不能当事实"）
L1 采集方式（决定怎么抓）
   ├─ 网站搜索（site 查询 + 域名过滤两种子方式）
   └─ 热榜/聚合接口（独立 API / JSON Feed）
L2 类别（决定展示分组与默认等级）
   ├─ 政府权威   → 默认 S（事实锚点）
   ├─ 权威新闻   → 默认 S/A
   ├─ 财经综合   → 默认 A/B
   ├─ 科技行业   → 默认 B
   ├─ 门户平台   → 默认 C
   ├─ 社区社交   → 默认 C
   ├─ 海外主媒   → 默认 A
   ├─ 海外社区   → 默认 C
   ├─ 境外华文   → 默认 A
   └─ 热榜榜单   → 默认 high（榜单客观，条目按源溯源）
L3 具体条目（可勾选 / 可手动添加）
   名称 | 域名 | 类别 | 采集方式 | 等级 | 启用
```

## 1.5 信源等级体系（S/A/B/C/D —— 报告里"什么是事实"的裁决规则）

| 等级 | 定义 | 典型 | 映射 credibility | 在报告/分析中的使用规则 |
|---|---|---|---|---|
| **S** | 官方机构 / 权威中央媒体 | 政府与监管部门发布、新华社、人民日报、央视、法院/监管公告 | high | **事实锚点**：时间/数字/事件的第一事实来源，注明"据官方/权威" |
| **A** | 主流权威媒体（含海外主流） | 澎湃、财新、凤凰、BBC、Reuters、FT、NYT、WSJ、Bloomberg、经济学人、卫报、联合早报 | high | **可作事实依据**，正文必须注明媒体名 |
| **B** | 行业/财经/门户媒体 | 36氪、虎嗅、第一财经、腾讯新闻、Ars Technica、爱范儿 | mid | 可引观点/深度分析；**事实需与 S/A 交叉验证**，单源 B 级事实标注"待核" |
| **C** | 社媒/自媒体/聚合导读 | 微博、知乎、B站、百家号、HN/Reddit 帖、Buzzing 导读条目 | mid/low | **仅作舆论样本/线索**，不得作为事实依据；引用必须标注来源平台与局限 |
| **D** | 无法核实/匿名网传 | 匿名帖、无出处的传闻 | low | 默认不进报告正文；确需引用必须标注"未经证实的网传信息" |

**裁决规则（写进 AI prompt 的硬约束）**：
1. 事实性信息（时间/地点/数字/事件）只用 **S/A** 级来源；
2. S/A 级素材缺失时，允许 B 级来源 + 标注"（据 XX 报道，权威媒体未见同类信息）"；
3. C/D 级仅用于"舆论倾向/代表性观点"章节，且必须标注来源平台；
4. 等级与现有 credibility 字段打通（S/A→high、B→mid、C→mid/low、D→low）。

## 3. 采集实现方式（按采集方式三选一 / 组合）

### 3.1 网站搜索 - site 查询（精确）
勾选网站 → 对该网站域名生成 `site:<host> <关键词>` 查询变体，追加到采集关键词序列。
- SearXNG 支持 site: 语法（部分引擎响应）；
- 优点：结果聚焦某站；缺点：收录不全、查询次数翻倍（需控制数量）。

### 3.2 网站搜索 - 域名过滤（兜底，默认主路径）
保留现有"多引擎全量搜索"，结果进入 pipeline 后按**勾选网站域名白名单**过滤/加权：
- 高可信网站（A/B 类）保留甚至加权；
- 其余在去重后按勾选集合截取；
- 复用现有 `domain_of` / `credibility` / `source_name`，无新依赖、零风险。
- **手动添加**：设置页填"名称 + 域名"，即加入白名单（本质是新增一条过滤规则）。

### 3.3 热榜接口 - 独立采集器 hotlists.py
**主通道：tophub.today 聚合解析（2026-09-01 实测可行，一个入口覆盖几十榜）**
- 榜单页 `/n/{hashid}` 为 SSR，条目（标题+链接+热度）直接渲染在 HTML，标准库解析即可；
- 已取真实 id：微博热搜 KqndgxeLl9 / 知乎热榜 mproPpoq6O / B站热门 74KvxwokxM / 百度热搜 Jb0vmloB1G / 抖音总榜 DpQvNABoNE / 头条热榜 x9ozB4KoXb；完整映射存 `backend/th_boards.json`（38 榜）；
- 采集方式：按 sources 表 hotlist 条的 `extra.tophub_id` 抓取解析 → `[{title, url, hot, source(榜单名)}]`；
- 失败/改版 → 静默降级并记录 warning，不拖垮主线；频率控制（每日 ≤6 次/榜）。
**备选：tophubdata.com（"今日热榜官方数据开放平台"）**
- 官方 API（通常需 key，可能收费），适合正式商用/高稳定性场景；暂不接入，页面解析满足事件发现用途。
**原有单榜直连可保留**：B站 `api.bilibili.com/x/web-interface/popular`（公开）等，作为 tophub 的交叉校验/降级。

### 3.4 JSON Feed 采集（Buzzing 类，零新依赖）
- 抓取 `https://www.buzzing.cc/feed.json`（单次 ~520KB），标准库 `json` 解析即可，无需 feedparser；
- 字段映射：`title`→标题｜`url`→原文链接｜`_num_comments`→热度｜`_site_identifier`→来源平台｜`_category`→分类；
- 可选按 `_category` 过滤（如只取 News/Finance 参与舆情分析）；
- 缓存策略：每日 ≤2 次拉取（内容为热门聚合，时效要求低于实时榜单），失败静默降级；
- 内容为机翻导读：素材中标注"Buzzing 中文导读"，事实溯源以 `url` 原文为准（符合"来源标注"铁律）。

## 7. 风险与约束

- **热榜稳定性**：第三方接口随时变 → 全部静默降级 + 状态展示，不阻塞主线；
- **合规**：只读公开内容、低频抓取、不绕登录墙、按 robots 精神控制频率；榜单数据仅做事件发现索引；
- **查询成本**：site: 变体会增加 SearXNG 查询量 → 默认仅对勾选且"精确模式"网站启用，控制数量（≤5 个/次分析）；
- **性能**：域名白名单过滤是纯内存碰撞（秒级），不影响现有耗时（249s 基线不变）。

## 10. 等级字段落点

- `sources` 表增加 `level`（S/A/B/C/D），内置目录直接标注；手动添加默认 C，用户可调整；
- 采集时把 level 并入素材（item["level"]），与 credibility 并存（level 是目录级规则，credibility 是结果级评估）；
