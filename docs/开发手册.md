# 舆情分析平台 · 技术开发手册

> 版本：v1.0 ｜ 更新：2026-08-31
> 产品口径：**部署后任何人打开前端页面即可直接使用，无需复杂配置；管理员最多只需在页面里添加 API Key、勾选信源。**
> 部署形态：Docker 一键部署；可打包为飞牛 fnOS FPK 安装包。

## 0. 开发规则（必读，全员遵守）

**状态流转规则：**

| 符号 | 含义 |
|---|---|
| ⬜ | 待开发（未开工） |
| 🔄 | 开发中（正在实现） |
| ✅ | 开发完成（代码/功能已就绪） |
| ✅✅ | **人工已验证**（真实使用场景下由人实际操作核对通过，标注验证日期与验证人） |
| ⛔ | 验证未通过/退回（写明原因，回到 🔄） |

**铁律：**
1. 每一项开发完成后，**必须**进入人工验证环节：开发者在浏览器/部署环境按"验收标准"逐条实际操作核对；
2. 验证通过 → 在下方状态表中把该项标为 `✅✅（已验证 20XX-XX-XX）`，并在"更新日志"登记；
3. 验证未通过 → 标 `⛔ 退回：<原因>`，回到 🔄 修到通过为止；
4. 只有 `✅✅` 的项才算交付，未验证的 `✅` 不代表可用；
5. 每次接手开发前：先读"现状盘点"和"状态表"，确认哪些已完成、哪些在验。

## 2. 现状盘点（v1.0 已具备）

| 模块 | 现状 | 文件 |
|---|---|---|
| 采集 | SearXNG 4 信源组（news/微信/主流/视频），相关性过滤（4-gram），URL+标题去重，三级可信度，媒体名识别 | backend/collector.py、searx_client.py |
| AI 分析 | 四段式（事实/原因/风险/对策），对策-风险 id 硬校验，媒体归属+权威事实约束，429 退避，空响应降级重试 | pipeline.py、ai_prompts.py、ai_client.py |
| 报告导出 | docx（对齐参考格式.docx）/ markdown / PDF（浏览器打印） | gen_docx.mjs（Node）、render_markdown |
| Web | Flask 页面：主题输入/进度轮询/报告预览/三格式下载/历史任务（内存） | app.py、frontend/index.html |
| 配置 | .env 文件（SearXNG 地址、AI provider、key、模型） | config.py |

**已知短板（本轮要解决的差距）：**
1. 配置靠改 .env + 重启服务（非产品化）；无可视化设置页；
2. 任务历史在内存，重启即丢；无 SQLite 持久化；
3. 无 Docker/FPK 打包；无访问控制；API key 明文在 .env；
4. 报告无情感/信源可视化，无热榜监测与定时任务；
5. 前端为单 HTML，功能骨架完成但交互与视觉未产品化；
6. 主模型为远程 flash 模型，单章生成 15-55s，总时长 3-4 分钟，用户体验需靠进度与降级设计补偿。

## 3. 目标架构（演进后）

```
┌─ 前端（单页，本地静态资源，ECharts 本地化，离线可用）─────────────┐
│  首页(主题输入/进度/报告/下载) · 设置页(管理员:AI+信源) ·          │
│  热榜发现 · 历史对比 · 报告编辑 · 监测任务管理                     │
└───────────────┬───────────────────────────────────────────────┘
                │ HTTP (同源 /api)
┌──── 后端 Flask (纯 Python，无 C 扩展依赖) ────────────────────────┐
│  auth(可选 token/登录) → 任务编排 → 采集层 → 清洗 → AI 分析 →     │
│  报告渲染(docx/md/pdf) → SQLite 持久化(任务/配置/历史/监测)        │
└───────┬───────────────────────┬────────────────────────────────┘
        │                       │
   SearXNG(可内嵌容器)      AI 网关(9router/DeepSeek/通义/
   或外部实例(可配置)        OpenAI 兼容，设置页可视化配置)
```

**技术约束（红线，防止踩坑）：**
- 后端保持纯 Python 依赖（本机企业策略拦截 C 扩展：lxml/pydantic/msgspec/chardet 等不可用；Docker 容器内不受此限，但为行为一致仍默认纯 Python）；
- 持久化用 `sqlite3`（stdlib），不引 ORM；
- docx 生成沿用 Node `docx`（backend/scripts/gen_docx.mjs）；
- 前端保持无构建：单 HTML + 本地 JS/CSS/ECharts（第三方库下载放 frontend/vendor/，离线可用）；
- 任何新依赖必须先验证本机可导入（`python -c "import xxx"`）。

## 4. 分期开发计划

> 每项含【验收标准】——人工验证时逐条打勾，全部通过才标 ✅✅。

### P-A 部署与零配置（最高优先：让"任何人打开即用"）

**A1a. 最小容器化（开发跑道，现在做）**
- 内容：Dockerfile（Python + Node/docx + 前端静态资源 + SQLite 数据卷），单容器跑通现有全部功能；SearXNG 仍用外部实例；代码挂载 + 自动重载，替代本机"改配置杀进程重启"工作流。
- 验收标准：`docker build && docker run -v ./backend:/app -p 5000:5000` 后浏览器可用，修改 Python 代码无需重启容器即生效；本机不再需要直接依赖系统 Python 环境。
- 状态：✅（开发完成，待人工验证——需 Docker 环境构建/导入，见 docs/DEPLOY.md）

**A1b. 交付级编排（软件成熟后打交付包）**
- 内容：docker-compose 全栈（app + 可选 searxng 容器）、健康检查、持久卷、标准端口、一键启动脚本（含首次初始化 .env/db）、.dockerignore 不含密钥。
- 验收标准：`docker compose up -d` 一条命令交付；普通用户无需编辑任何文件即可运行；容器内可生成 docx/md/pdf。
- 状态：⬜

**A2. 飞牛 fnOS FPK 打包**
- 内容：参考本机已有项目 `D:\AI编程\fnos-tv` 的 fpk 结构（package.json/fpk 打包脚本/install 服务接管），产出 `livelist.fpk` 类似物：启动脚本、端口约定、依赖说明（系统需 python3/node）。
- 验收标准：在 fnOS 上安装后应用可启动；局域网访问后端页面；卸载干净。
- 状态：⬜

**A3. 可视化设置页（AI + 信源 + 通用偏好）**
- 内容：新增"设置"页（管理员可见）：AI provider 表单（网关地址/key/模型，支持 9router/DeepSeek/通义/OpenAI 兼容，`model: "provider/model"` 风格）、信源组勾选与自定义引擎、SearXNG 地址、默认主题示例；配置写入 SQLite（settings 表），前端不接触 key（服务端打码回显）。
- 验收标准：页面完成配置保存后**无需重启服务**立即生效（config 热重载）；key 在前端只显示 `sk-****`；配置缺省时有引导提示；普通用户看不到设置菜单。
- 状态：✅ 开发完成（2026-08-31：设置页/API/脱敏/信源组开关已实现并本地验证）｜⏳ 待人工验证：页面上改配置→保存→立即生效；key 仅打码显示；信源取消勾选后下次分析不再采集该组

**A4. 新增开发：配置热重载**
- 内容：config.py 加 `reload()`；每次任务开始前刷新配置（读取 SQLite 覆盖 .env）。
- 验收标准：A3 保存后下一次任务使用新配置；.env 仍作为默认值来源。
- 状态：✅ 开发完成（reload() 已实现，任务入口已接入）｜⏳ 待人工验证：设置页保存后直接发起任务，新配置生效

### P-B 用户体验与界面

**B1. 报告页可视化增强**
- 内容：报告顶部加可视化区：情感占比（正/负/中立，参考 ai-sentiment-analyzer）、信源分布、时间趋势（ECharts 饼图/柱状图）；数据来自 AI 分析的中间结果或素材统计。
- 验收标准：能展示 3 种图表；无 AI 数据时优雅降级（显示素材统计）；导出 PDF 时图表可见。
- 状态：✅ 开发完成（2026-09-01）——ECharts 本地化 + facts 复用输出 emotion/quotes + 规则统计源分布/时间趋势 + 前端三图与观点卡片；实测数据齐全｜⏳ 待人工验证

**B2. 代表性评语/观点卡片**
- 内容：报告页"观点摘录"区：从素材中按可信度与情感挑 3-6 条代表性观点（标题+媒体+引用句），正/中/负分组展示。
- 验收标准：卡片含来源媒体与链接；可点击跳转原文（新标签）。
- 状态：✅ 开发完成（2026-09-01）——与 B1 同批交付（quotes 卡片：立场标签/来源/原文链接）｜⏳ 待人工验证

**B3. 历史持久化与对比**
- 内容：任务/报告落 SQLite；历史列表分页检索；同一主题的多次报告可并排对比（章节段落对照）。
- 验收标准：重启服务后历史仍在；同主题两次分析可对比视图；检索按主题/日期。
- 状态：✅✅ 2026-09-01 人工验证通过（首页 5 条收敛、×2 徽标、历史页每页 10 条分页、报告文件页面内预览；重启持久化 PASS：4 任务 + 47 文件重启后完整保留）

**B4. 报告在线编辑（Artifact 简化版）**
- 内容：报告页"编辑"模式：把章节内容改为可编辑（Markdown 文本域），保存后可重新导出 docx/md/pdf。
- 验收标准：改一段文字保存，再下载 docx 内容与修改一致；可还原。
- 状态：✅✅ 2026-09-01 人工验证通过（改文→保存→导出核对→还原 全链路正常）

## 7. GitHub 自动同步（新对话接手必读）

> 每次代码变更后都应同步 GitHub：push 自动触发 Actions 构建新镜像（ghcr.io/ruoshui6662/miaoyu-analysis:latest），飞牛 `docker compose pull && docker compose up -d` 完成升级。

**仓库地址**：`https://github.com/ruoshui6662/miaoyu-analysis.git`（Public）
**推送到镜像**：`ghcr.io/ruoshui6662/miaoyu-analysis:latest`（GitHub Actions workflow 自动构建）

**令牌（PAT）**：**不写入任何会同步到 GitHub 的文件**（仓库是 Public，GitHub secrets 扫描会拦截明文 PAT，且会泄露）。
- 存放位置：本地 `D:\AI编程\舆情\.env` 的 `GITHUB_PAT=` 行（`.env` 已被 `.gitignore` 排除）；
- 新对话/新环境接手：先 `grep GITHUB_PAT .env` 确认令牌仍有效（若 GitHub 端已轮换，同步更新本地 .env）。

**同步流程（两种等价方式）**：
```bash
# 方式一（推荐）：自动脚本（从 .env 读令牌，自身不含明文）
bash backend/sync_github.sh "feat: 本次改动说明"

# 方式二（手动）：
git add -A && git commit -m "说明"
git push "https://ruoshui6662:${PAT}@github.com/ruoshui6662/miaoyu-analysis.git" main
# 注意：不要用会把 PAT 写进 .git/config 的方式（remote URL 带 token 会明文残留）
```

**安全提醒**：
- PAT 出现在对话/命令行时即视为已暴露，倾向轮换（GitHub Settings → Developer settings → Tokens → 删除重建，权限 `write:packages` + `workflow` + `repo`）；
- 若推送被 GitHub 以 "repository rule violations" 拒绝：几乎一定是提交内容里出现了 PAT 明文，检查并移除后重试（可用 `git log --all -S ghp_` 检索）。
